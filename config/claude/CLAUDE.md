## Communication

- Put the answer first, keep lists short, make progress visible, end with one concrete next step.
- Optimize for execution over explanation.
- NEVER use emoji, or unicode that emulates emoji.

## Workflow

- ALWAYS write tests for new behavior and bug fixes BEFORE implementing them (TDD).
- NEVER push to git without asking first.
- Refactor only when essential or explicitly requested.

## Code style

- Follow YAGNI and KISS. Prefer the simplest working solution.
- MUST avoid redundant comments that restate what the code already shows.

## Scope control

- Implement exactly what the task specification and acceptance criteria require.
- Cover specified edge cases; do not add unrequested functionality.
- Keep changes minimal and targeted; only modify what is necessary.

## Flag issues when found

- Confusing names, duplicated logic, dead code.
- Missing or brittle tests.
- Unsafe assumptions, unclear boundaries.
- Poor or stale documentation.
